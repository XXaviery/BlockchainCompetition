# MOF-Robot 电脑—树莓派双端同步协议

> 建立日期：2026-08-13  
> 适用范围：`firmware/`、ROS2 包、测试工具、配置和调试留痕
> 核心原则：电脑工作区是唯一持久真源；树莓派是经过校验的部署镜像和运行环境。

## 1. 为什么必须执行本协议

此前存在两类修改：

- AI 通过 SSH 直接修改树莓派源码，但电脑没有同步。
- 后续任务又修改电脑本地旧版本，可能覆盖或遗漏树莓派上的新内容。

因此“能够运行”不再等同于“源码一致”。以后每次部署和实车测试都必须先完成双端对账，并以逐文件 SHA-256 一致作为部署完成条件。

## 2. 唯一真源与目录角色

### 2.1 电脑本地

电脑源码位置（相对于竞赛项目根目录）：

```text
code/robot
```

若单独解压硬件源码包，则解压后的 `mof_robot/` 即同一源码根。不得把任一电脑盘符或用户目录写成源码定位依据。

职责：

- 唯一允许进行持久源码编辑的位置。
- 保存 Git 工作树、设计文档、最终配置和调试工具。
- 保存每次部署前后的 diff、哈希和回滚记录。
- ESP32 固件必须从这里构建；树莓派不得成为固件源码真源。

### 2.2 树莓派

树莓派职责：

- 接收电脑本地已验证文件。
- 构建 ROS2 包并运行实车测试。
- 采集运行日志、rosbag、话题、TF 和串口遥测。

树莓派上的 `src` 是部署镜像，不是独立开发分支。禁止使用远端编辑器、`sed -i`、Python写文件、重定向或补丁直接持续修改树莓派源码。

### 2.3 临时文件

树莓派 `/tmp` 中的测试脚本只允许由电脑本地同名脚本复制生成。`/tmp` 内容不是源码，不得在远端修改后直接当作下一次运行版本。

### 2.4 不要求逐字相同的目录

以下属于生成物或运行数据，不参与“源码一致”判定：

```text
build/
install/
log/
__pycache__/
.pio/
rosbag/
地图运行产物
远端备份目录
```

一致性比较对象是电脑 `firmware/`、ROS2 包源码、配置、launch、脚本和相应文档，而不是生成目录。

## 4. 每次任务开始时的强制对账

### Phase R0：冻结运行

- 不发布任何非零速度。
- 不写 NVS。
- 不烧录固件。
- 不直接修改树莓派源码。
- 如果树莓派存在运行节点，先只读确认机器人全零；需要停止时按完整进程组安全停止。

### Phase R1：发现真实远端路径

不能假设树莓派工作区一定叫 `ros2_ws` 或 `ros2_ws`。必须只读确定：

- 实际源码包路径；
- 实际 `install` 前缀；
- 当前 shell source 的工作区；
- 实际运行节点来自哪个安装路径。

将最终路径追加到 `DEBUG_ARCHIVE.md`。后续本次任务只能使用这一个路径。

### Phase R2：生成双端清单

分别生成电脑和树莓派关键文件的：

```text
相对路径
文件大小
修改时间
SHA-256
```

至少覆盖：

```text
ros2_ws/src/mof_esp32_bridge/package.xml
ros2_ws/src/mof_esp32_bridge/setup.py
ros2_ws/src/mof_esp32_bridge/config/**
ros2_ws/src/mof_esp32_bridge/launch/**
ros2_ws/src/mof_esp32_bridge/mof_esp32_bridge/**.py
ros2_ws/src/mof_esp32_bridge/README.md
firmware/src/**
firmware/lib/**
firmware/platformio.ini
tools/*.py
```

对于树莓派不存在的电脑专用目录（例如 `firmware/` 或根目录 `tools/`），要明确记录“电脑真源、未部署”，不能伪造一致。

### Phase R3：处理远端独有修改

若发现树莓派源码和电脑不同：

1. 先把远端不同文件复制到电脑的时间戳恢复目录。
2. 逐文件查看 diff，判断哪些是有效远端修改。
3. 将需要保留的内容合并进电脑本地文件。
4. 在电脑本地完成静态检查。
5. 只有本地版本确定后，才允许重新部署。

禁止：

- 未查看 diff 就整目录覆盖电脑。
- 未备份就整目录覆盖树莓派。
- 使用 `rsync --delete`。
- 因为树莓派版本“刚刚运行过”就默认它一定更新或正确。
- 因为电脑文件修改时间较新就默认电脑内容一定完整。

本次已知 `ros_safe_roundtrip_test.py` 是电脑端较新的部分实现；必须以电脑 WIP 为基础继续完成，远端旧脚本只能作为对照，不能回灌覆盖。

## 5. 唯一允许的编辑—部署事务

每轮修改使用以下闭环：

```text
本地对账完成
→ 只在电脑编辑
→ 本地语法/YAML/diff检查
→ 记录本地SHA-256
→ 远端创建时间戳备份
→ 上传到远端暂存路径
→ 暂存文件SHA-256与本地比较
→ 覆盖远端src中的明确文件
→ 重新生成远端src SHA-256
→ 与本地逐文件比较
→ colcon构建
→ 检查实际install前缀
→ 启动零速链
→ 运行测试
→ 将运行结果追加回电脑DEBUG_ARCHIVE.md
```

任何一步失败都停止闭环，不得带着“部分同步”进入运动测试。

## 6. 部署文件白名单

每次只上传本轮明确修改的文件。不得默认整目录覆盖。

部署记录必须包含表格：

| 相对路径 | 修改原因 | 本地SHA-256 | 远端SHA-256 | 状态 |
|---|---|---|---|---|
| 示例 | 示例 | 示例 | 示例 | `MATCH/MISMATCH` |

只有所有计划部署文件均为 `MATCH` 才能构建。

构建成功不等于源码一致；仍需核对 `src` 哈希和 ROS 实际使用的 `install` 前缀。

## 7. 实车测试前的同步 Gate

所有非零运动前新增 Sync Gate：

- 电脑是本轮唯一编辑端。
- 已记录真实远端源码路径和安装路径。
- 本轮修改文件白名单明确。
- 本地静态检查全部通过。
- 白名单文件本地与远端 `src` SHA-256 全部一致。
- 远端构建成功。
- 当前 ROS 节点来自刚刚构建的安装前缀。
- `/tmp` 测试脚本哈希等于电脑本地工具脚本哈希。
- `DEBUG_ARCHIVE.md` 已记录部署清单和回滚路径。
- 随后才进入 `NAVIGATION_MAINLINE.md` 的 Gate 0。

Sync Gate 未通过时只能做只读诊断和零速检查。

## 8. 远端临时修复的例外处理

原则上不允许远端持久修改。若为了恢复 SSH、验证权限或紧急停车必须改变远端运行状态：

- 只允许操作进程、权限或临时文件，不直接编辑项目源码。
- 如果确实发生远端源码修改，立即停止后续任务。
- 先把修改文件完整复制回电脑恢复目录并合并进本地。
- 重新走本地检查、部署和哈希闭环。

在远端修改未回收前，不允许再进行新的电脑端源码修改，以免形成第二次分叉。

## 9. 树莓派离线时的工作规则

树莓派无电或离线时，可以：

- 在电脑本地继续实现代码。
- 进行语法、YAML、单元或静态检查。
- 更新文档和调试记录。

但必须明确标注“仅本地、尚未部署”。树莓派恢复后先执行完整双端对账，不能直接从上次远端运行状态继续。

## 10. 当前恢复任务的执行顺序

树莓派已经重新启动，但当前本地 P0 仍是部分实现。下一步必须：

1. 只读发现树莓派真实源码和安装路径。
2. 生成双端关键文件哈希清单。
3. 备份所有差异文件，确认没有未回收的远端独有代码。
4. 以电脑本地 713 行 WIP 脚本为基础完成 P0，不能使用远端旧脚本覆盖。
5. 完成 `velocity_timeout=0.3`、旧安全入口、`.gitignore` 和留痕修改。
6. 完成本地 AST、YAML、diff 和哈希检查。
7. 从电脑部署白名单文件到树莓派。
8. 本地与远端逐文件 SHA-256 一致后构建。
9. 先执行零速 Gate，再进入真实 Collision Monitor 拦截。

当前禁止直接执行旧的 `--zero-only` 超时任务或任何非零运动，因为脚本状态机和最终消息因果验证尚未完成。

## 11. 每次任务结束时的交付

必须明确报告：

- 本轮电脑修改文件。
- 本轮树莓派部署文件。
- 本地与远端源码路径。
- 每个部署文件的双端 SHA-256。
- 构建结果和实际安装前缀。
- 是否仍存在仅本地或仅远端文件。
- 当前机器人停止状态。
- 远端回滚目录。
- `DEBUG_ARCHIVE.md` 新增位置。

如果还有任何 `MISMATCH`，任务状态必须写“同步未完成”，不能声称阶段完成。
