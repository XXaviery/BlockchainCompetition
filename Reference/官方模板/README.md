## 5. 历史残留与使用风险

### 附件 1：项目创意书

- 标题使用“模版”写法，属于官方原文。
- 内容是通用创意书框架，没有针对“其他人工智能应用”的算法实现、数据、测试和工程证据专栏。
- 若用于本项目，应补足人工智能问题定义、输入数据、算法/规则状态、系统实现和证据边界。

### 附件 2：设计与开发文档

- 第三章“详细设计”仍出现“链基础环境”。
- 第五章“安装及使用”仍要求说明“链基础环境”。
- 对本项目应根据实际情况改为“运行与部署环境”或“硬件、操作系统、中间件及算法环境”；不得为了保留旧字段强行加入区块链。
- 模板将测试报告作为第四章，但本赛道官方同时把“测试报告”列为提交材料之一。最终是合并在设计文档内还是另交独立文件，需以报名平台字段为准。

### 附件 3：著作权授权声明

- 标题写作“著作权授权申明”，属于官方原文。
- 正文仍两次出现旧称“全国大学生‘区块链+’应用大赛组织委员会”。
- 落款日期仍为“2025 年 月 日”。
- 正式签署前应向组委会或报名平台确认是否使用平台动态生成的新声明。未经确认，不直接改写官方法律文本后冒充官方模板。

### 附件 4：作品提交要求（未拆分为模板）

- 位于官方手册第 22 页。
- 目录示例仍使用旧赛道名称和 `2024...` 作品编号示例，并含“区块链+音乐”“区块链+数媒设计”等历史分类。
- 该页不能直接作为“其他人工智能应用”当前目录结构的唯一依据。

## 6. “其他人工智能应用 → 自选命题”建议调整字段

以下调整用于团队自建文档，不代表改写官方 PDF：

- 项目名称、作品编号、学校、作者、指导教师、日期按报名平台最终信息填写。
- “链基础环境”改为实际部署环境；如无区块链，不填写虚构内容。
- 技术方案增加：AI 要解决的问题、输入数据、预处理、算法或规则、输出、评价指标、失败边界。
- 实现成果只填写有代码、实物、截图、日志或视频支持的内容。
- 测试章节区分材料级、模块级和整机级数据。
- 第三方模型、数据、代码、图片和其他素材分别记录来源、许可与授权。
- 若当前仅有规则决策而无机器学习模型，应如实说明，不使用“已训练模型”“预测准确率”等表述。

## 7. 最终提交前复核清单

1. 登录报名平台并选择准确赛道与小类。
2. 截图保存平台显示的字段、必填标记、文件格式、大小限制和截止时间。
3. 检查是否出现新的 DOCX、在线表单或赛道专属模板。
4. 核对授权声明是否由平台自动生成，旧组织名称和年份是否已修正。
5. 核对测试报告是独立上传还是并入设计文档。
6. 核对代码文件夹链接是必填、选填还是仅供评审查看。
7. 最终材料以当时平台要求为准，并保留提交成功页和时间截图。
